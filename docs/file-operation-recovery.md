# 文件操作与恢复（0.3.42）

阶段 B 保持主索引 `index.json` v5、设置与其他缓存格式不变，只把 `pending-operations.json` 从 v1 升级到 v2。应用仍只在用户明确确认后执行重命名或回收站删除。

## 重定位与重命名

- 重定位按条目 kind 选择文件或文件夹；选择请求绑定 ID、原路径、kind 和导航上下文，取消或过期选择不提交。Rust 在提交锁内再次确认条目与来源修订、失效状态、目标类型及重复路径。排序后的返回条目保持请求 ID。
- 重命名与重定位共用当前记录的元数据合并，只更新路径、名称、格式和文件系统字段。收藏、标签、分组、添加时间、最近记录、最近打开和预览状态保留提交时的值。
- 同一资料的重命名、删除和重定位互斥；无关资料预览不持有该操作锁。重命名持久化失败后只对仍匹配来源快照的文件回滚；Windows `MoveFileW` 不覆盖目标路径中新建的文件。回滚失败返回 `partial-success` / `unknown`，需刷新后检查路径并重新定位。

## 删除日志顺序

1. 保存 `prepared`，包含资料 ID、原路径、登记时间、索引来源字段，以及文件大小和高精度创建/修改时间快照。保存失败时不开始物理删除。
2. 对已验证的来源执行回收站操作；物理结果不明时保留日志。自动恢复不会再次执行物理删除。
3. 物理操作成功后保存 `physical-complete`。此处失败时磁盘仍为 `prepared`，原路径缺失不等于成功证据，界面保留待核对状态。
4. 在索引提交锁内确认目标条目仍对应原来源、原路径确实不存在，再保存移除后的索引。
5. 索引成功保存后清理日志。日志清理失败时保留已经保存的新索引；不尝试反写旧索引。重启可根据没有对应条目幂等清理日志。

两份 JSON 各自采用原子写入，不构成数据库事务。中途退出依靠上述顺序与来源复核恢复，普通读错误、权限错误和不安全路径不会被当作“文件不存在”。

## 恢复规则

| 情形 | 处理 |
| --- | --- |
| prepared，原来源仍存在且快照一致 | 结束未执行完的意图，保留资料和原文件 |
| prepared，来源缺失、改变或不能访问 | 保留日志和资料；刷新后可从待核对菜单检查资料、回收站，再重新定位或明确移除索引记录 |
| physical-complete，来源缺失且记录仍匹配 | 保存对应索引移除，再清理日志；重复恢复不重复删除 |
| 原路径出现新文件 | 保留新文件和记录，不继续操作此路径 |
| 条目已重定位、重新登记或已被用户移除 | 不移除新记录，结束旧日志 |
| 文件操作仍在执行 | 恢复跳过该操作，重建空索引拒绝执行 |
| 索引损坏 | 保留索引恢复状态，不把空的内存视图当作日志已经完成的证据 |

重建空索引前展示资料、分组和 pending 数量，确认后清空索引、撤销记录及 pending，不删除原文件。先保存空索引，再清理日志；第二步失败时返回错误并保留警告，再次刷新或重启能按空索引收敛。

## 迁移与验收

- 读取 v1 日志时先保留原始字节备份，再写 v2；旧条目缺少来源快照，明确保留 `source: null`，不推断旧 prepared 或 physical-complete 的结果。用户核对后通过重定位、移除记录或确认重建结束旧日志。
- 备份或迁移写入失败时不覆盖原日志；恢复磁盘空间或访问权限后重试启动。日志通常在清理完毕后删除。
- 旧版 `0.3.41` 不识别 v2 pending，回退前应先在 `0.3.42` 结束待核对操作并确认日志已清理。不得让旧版自动恢复机制代替新日志的核对。
- 定向回归使用隔离临时资料，通过屏障复现重命名与元数据修改并发；注入 prepare、mark、索引保存和日志清理失败。自动测试不操作系统回收站或用户真实资料。
- Windows 11/Tauri/WebView2 的选择器、回收站、文件占用、安装升级和重启验收由用户执行；浏览器和构建证据不替代原生验收。
