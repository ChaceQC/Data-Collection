# 正文索引与查询（0.3.43）

阶段 C 修复 R02、R11，并将正文查询放入受控 blocking worker。正式发布基线仍为 v0.3.40；0.3.43 是本地候选，Windows 11/Tauri/WebView2 原生验收待用户完成。

## 缓存边界与兼容

正文仅保存在 Tauri app data 的 `content-index.json`，格式继续为 v1；主索引 v5、收藏、标签、分组、原文件及数据目录不受缓存恢复影响。

| 项目 | 上限 | 计量方式 |
| --- | --- | --- |
| 源文件 | 2 MiB | 实际读取字节数 |
| 单条解码正文 | 2 MiB | UTF-8 字节数 |
| 单条字符 | 1,000,000 | Unicode scalar value，非 UTF-16 code unit |
| 全部正文 | 64 MiB | 单条 UTF-8 字节数之和 |
| 缓存条目 | 20,000 | 唯一资料 ID |
| JSON 文件 | 72 MiB | 包含结构、路径和转义的序列化字节数 |

源文本继续复用预览的 UTF-8 BOM / UTF-8 / GB18030 解码器。80 万个汉字的 GB18030 源文件为 1,600,000 字节，解码为 2,400,000 UTF-8 字节，因此跳过当前资料，状态和重建摘要提供具体限制类别。错误信息不包含正文或真实完整路径。读取前后复核 metadata 和来源路径，变化时跳过，等待刷新。

启动、增量同步、重建与保存共用条目规则。旧 v1 文件中的无效、重复或超限条目先通过受控 app-data 备份，再隔离并保存其余可读缓存，状态显示隔离数量。根 JSON 无法解析、未知版本或无法备份时保留恢复流程；不静默重置资料库。保存前校验总量和条目，序列化缓冲也受 72 MiB 上限约束，原子写入成功后才发布新快照。写入失败继续保留此前可用正文。

旧 0.3.42 可以读取新候选写出的 v1 缓存，但其旧写入逻辑可能再次生成超限正文；回退后出现缓存恢复提示时可清除或重建正文，不应重置主索引。

## 顺序与查询

- 文档和快照使用 `Arc` 共享；查询获取快照不复制正文，扫描不持有正文写锁。增量同步只复制 ID 到文档的映射，未变化正文继续共享。
- 增量同步先移除已删除、失效和待替换的正文，再读取新增或变化文件并计算容量。清除和重建递增内存任务代次，废弃较早同步和查询；`sourceRevision` 保持单调。
- 清除只删除当前缓存并丢弃此前待处理同步；后续新资料 revision、显式重建或应用下次启动恢复自动更新。这不是永久关闭正文索引。
- 取消重建保留此前可用快照；从 recovery 开始的取消仍保留 recovery。后台同步仍按主索引 revision 合并最新待处理任务；整库文件 metadata 扫描的进一步优化属于阶段 F。
- `search_content` 为异步 command，参数新增 `requestId`，响应回传相同 ID；`cancel_content_search` 只在主窗口获得权限。非法 ID、取消、超时和繁忙使用结构化错误类别。
- Rust 全局最多接纳两个正文查询任务，其中一个扫描、一个等待；新请求取消旧请求，超额请求返回繁忙。许可在任务退出后释放，取消不会提前放开仍在运行的槽位。
- 查询使用 2 秒协作式截止时间，在文档、表达式和命中间检查；单次 regex 调用不能强制中断，仍受 2 MiB 单文档、256 字符表达式、64 KiB regex 程序和 DFA 限制。这不是严格的 2 秒实时保证。
- 前端 140 ms 防抖之外，最多有一个在途调用与一个最新待执行请求。输入变化、清除、重建、导航离开正文和卸载使旧回调失效；失败后可再次输入或重建恢复。
- 状态新增仅驻留内存的 `cacheRevision`，每次发布正文或状态快照递增，解决同一 `sourceRevision` 下清除、重建和搜索乱序。它不写入 v1 文件；前端拒绝较小缓存修订及来源修订。

## 摘要与验证

摘要使用 Unicode 字符坐标，实际 `...` 前缀占 3 个字符；每段正文最多 240 字符，前后省略号最多各 3 字符，每结果最多 3 段、最多 64 个命中。只在发现第 65 个命中时将计数标为截断；空匹配不计数。长命中显示受限片段，高亮不会越过最终摘要。前端 runtime validator 使用相同字符坐标验证范围。

`prototype/shared/content-snippet-cases.json` 覆盖开头、中间、末尾、多命中、长命中、中文和非 BMP 字符；Rust 比较真实序列化结果，前端使用实际 `SearchHitSummary` 渲染并核对 `<mark>` 内容。`npm.cmd run test:content` 包含模型、契约、真实 Hook 和组件渲染回归。Rust 定向入口为 `cargo test --locked --lib storage::content`。

用户原生验收项目：中文正文检索与高亮、退出重开、超限项提示、清除后重建、取消重建、快速输入与失败恢复。开发侧回归、Edge 合成页面和本地安装包不代替该验收。
